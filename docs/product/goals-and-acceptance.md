# 常駐ホストの製品目標と完了条件

[製品文書索引](README.md) / [製品目標 Issue #189](https://github.com/O2-CONNECTIVE/rescue-host/issues/189)

更新: 2026-11-05。
これは #189 に対応する製品目標と受入の読み方です。
実装済み機能と実証済み範囲は [検証状態](../tether-pilot-status.md) に記録し、ここでは実装の合格数を持ちません。

## 利用者に提供する体験

利用者は、自分の Mac / Windows でホストの待機を ON にします。
認証と認可を通った操作クライアントが MCP 経由で対象ホストへ仕事を依頼し、同じ作業の進捗、出力、終了結果を受け取ります。
ホスト利用者は作業状況を確認し、待機を OFF にして新規作業を止め、実行中の所有作業を停止して回収できます。
停止や回収を確認できないときは、未確認の事実が見える体験を目指します。

ホスト UI の中心は待機 ON/OFF と作業状況です。
通常の依頼ごとの承認待ち管理画面や詳細な期限設定画面の拡充は、基本の実接続、作業、結果受領、停止と回収が成立した後に扱います。
初回登録、本人の同意、権限拡大、許可の寿命と失効は別途設計し、現行契約を変更するまで既存の確認を維持します。
待機 ON 自体は操作許可を発行しません。

## 優先順位と3系統の完了判定

最初の完成対象は、利用者の開発 PC である Mac です。
検証は次の順で進めます。

1. Mac 内で MCP サーバーをセルフホストし、接続、ツール一覧、有限作業、結果受領、停止と回収を確認する。
2. 外部の実 MCP クライアントから同じ Mac へ安全に届く経路を追加し、Mac GUI と一連の実接続を確認する。
3. 次の完成対象として Windows GUI と実 Windows ホストへの接続を確認する。

Mac 内の試験成功だけで、外部クライアントからの接続を完成扱いにしません。
セルフホストはサーバーの実行場所の選択であり、外部からの到達性や操作認可は別に必要です。
到達経路や認証の提供者を製品本体の必須依存とせず、追加機能は必要な用途と互換性を確認してから選びます。
既存の認証と認可を迂回する試験にはしません。

進行中の Windows レーンは継続し、Mac 先行を作業中断や検証停止の理由にしません。
各系統で「実接続 → 簡単な作業 → 結果受領 → 停止と回収」を通し、同じ固定版の一連の証跡として判定します。
安全に必要な認証、認可、所有、停止の契約は、その実証前に確認します。

| 系統 | 必要な実証 | 単独では合格にしないもの |
| --- | --- | --- |
| MCP 接続 | 実 MCP クライアントの呼出しから、まず実 Mac で有限作業を行い、同じ作業の結果、取消、ホスト OFF の反映を確認。Windows 接続は別に記録する | schema discovery、別クライアントの成功、CLI だけの実行 |
| Mac GUI | 実 Mac の画面から同じ一連の操作を確認し、MCP と GUI の状態が一致することを確認する | 読取専用 viewer、合成 pipe、別 snapshot の native 試験 |
| Windows GUI | 次の完成対象として、実 Windows の画面から待機 ON/OFF、実 MCP 接続、作業、結果表示、新規受付拒否、所有作業の停止と回収を確認する | 静的画面、合成状態、ビルド、GUI 起動だけの確認 |

Mac の縦断は Windows の完了を待たず個別に判定し、Mac の成功だけで両 OS 対応完了とはしません。
この完成順に沿って、待機、端末状態、再接続、作業照会をつなぎ、普段使いできる常駐版を整えます。
その後 #188 の専用操作を読取と検索から入力と編集へ広げます。
端末選択の安全性は最初から必要ですが、複数端末の一覧など辞書全体の実装を初回縦断の前提にはしません。
共通化は各接続をつなぐ範囲から進め、全面的なコード移動を着手条件にしません。

### 各系統で残す受入記録

各試験の前に、対象、許可操作、接続経路、停止方法、回収対象を固定します。
以下を OS と系統ごとに記録し、未実施、失敗、結果不明を残します。

1. source SHA、実行版、OS、クライアント、接続経路と、その試験の許可範囲を特定する。
2. 有限作業1件を実行し、同じ実行の状態、出力、終了結果を受け取る。
3. 別の停止可能な作業で取消を確認し、さらに作業中のホスト OFF と新規要求拒否を確認する。
4. 停止受付、所有 process の終了、所有 I/O と資源の回収を個別に確認する。
5. 未認可要求、接続失敗、結果不明、回収未確認で成功表示や無断再実行にならないことを確認する。
6. 公開する要約に秘密、実 identity、端末固有の path や endpoint、原ログを含めない。

作業終了と端末実行プログラムの終了、取消受付と回収確認、GUI 閉鎖と待機 OFF は別の事象として記録します。
source 試験、CI、実クライアント接続、実 OS 実行、GUI 操作、配布物の受入を分け、一つの成功を別の合格へ加算しません。
対応 OS と配布方式も、それぞれの実証がそろってから案内します。

## 共通処理を置く境界

採用する構成方針はヘキサゴナル構成です。
具体的な package 名や移動先は [#32](https://github.com/O2-CONNECTIVE/rescue-host/issues/32) と [#188](https://github.com/O2-CONNECTIVE/rescue-host/issues/188) の設計で確定します。

| 境界 | 担当する責務 |
| --- | --- |
| domain / application | 状態遷移、認可確認、実行所有、結果照会、冪等性、停止と回収の共通ルール |
| 入口 adapter | MCP、GUI、CLI の入力と結果を共通の処理へ変換する |
| 出口 port / adapter | 通信、OS 実行、保管、時計の違いを扱う |
| OS ごとの capabilities | 対応操作と保証差を示し、未対応操作を拒否する |

MCP や GUI ごとに別の許可ルートを作らず、OS ごとの実装を共通の契約試験と実接続で照合します。
接続と認証の提供者に固有の処理も adapter として分離し、製品本体と独立に選べる構成にします。
既存内部 package をそのまま公開 API と宣言せず、既存の `backend/`、GUI、module 境界は今回の文書整理で移動しません。

## 保持する安全条件と対象外

認証済みであること、待機中であること、操作許可があること、実行中であること、回収済みであることを分けます。
現行の本人同意、期限、失効、接続世代、所有範囲の契約を維持し、変更が必要なら対象契約と判断を別途記録します。
再接続や再起動で旧許可を自動復活させず、結果不明を新しい要求 ID で自動再実行しません。
認証期限の変更案や限定試験の条件を、そのまま製品既定値にしません。

Mac の現在ユーザー権限による実行は sandbox ではありません。
Windows の保護方式と同じ保証を持つとは扱わず、停止できる所有範囲も OS ごとの証跡で示します。
実行済みの副作用を停止で戻せるとは保証しません。
回収未確認は非成功として残します。

無承認の登録、自動的な権限拡大、MCP による本人同意の代行、人向け SSH 互換、任意 OS process の停止、無制限の常駐作業は、この最小縦断の対象外です。
一般配布、署名、初回登録、配布先での起動は別の受入であり、接続成功で完了にしません。
[既存安全受入 #1](https://github.com/O2-CONNECTIVE/rescue-host/issues/1)、[二重停止故障 #5](https://github.com/O2-CONNECTIVE/rescue-host/issues/5)、[Windows 背圧 #6](https://github.com/O2-CONNECTIVE/rescue-host/issues/6) の未達と未検証を維持します。

## 未決事項

以下は #189 の製品方向の合意だけでは確定しません。
各実装の着手時に必要な項目を解決し、[Decision #36](https://github.com/O2-CONNECTIVE/rescue-host/issues/36) と詳細設計へ対応づけます。

- 初回登録、同意導線、認証情報の保存、更新、失効。
- 作業許可の粒度と寿命、常駐制御接続との関係、ファイル操作の許可範囲。
- 切断、再接続、再起動、sleep/wake 時の許可と所有作業の扱い。
- OFF 後の具体的な失効処理、停止保証の範囲と時間、回収責任。
- ウィンドウを閉じる操作と待機 OFF の関係。
- 状態と schema の正本、結果と診断の保持期間、対応 OS と architecture、配布方式。

未決項目を新しい許可や実装済み機能として補いません。
#189 の整理完了と、3系統の実装完了、単発版 #22 の完了、配布可能の判断は、それぞれ別に記録します。
