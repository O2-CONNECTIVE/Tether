# 旧セッションの記録の扱い

[READMEへ戻る](../README.md)

旧 Windows 版（Python/Tkinter）は、GUIの起動時に保存済みの旧セッションの記録を読み、停止要求を出す回復経路を持っていました。GUIは[#407](https://github.com/O2-CONNECTIVE/Tether/issues/407)、回復と期限監視の処理（`rescue_core.py`、`rescue_watchdog.py`）は #416 で削除しました。

旧版が残した`active_session.json`と`sessions/<session-name>.authorized_keys`を、このリポジトリのコードでは回復できません。新規接続は無効だったため、新たな記録は作られません。

## 記録と終了の確認

終了を証明できない記録を消して解決したことにしません。名前付きの`ended`応答、終了コード、`not found`だけでは終了の証明になりません。画面を閉じることや鍵ファイルの削除は、接続の停止を意味しません。

旧版の記録が残るPCでは、承認済みの対象環境で実プロセスと通信の終了を確認してから記録を消してください。

停止できても、既に行われた変更や取得された認証情報は元に戻りません。[安全要件](security.md)とv0.2.1の公開レビュー（過去の参照資料・本文非同梱）を参照してください。
過去の引き継ぎ（過去の参照資料・本文非同梱）とレビュー（過去の参照資料・本文非同梱）にある明示的な終了応答による自動整理は、v0.2.1で撤回しています。
